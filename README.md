# ATP Tennis Analysis – AWS Automation

An automated data processing pipeline built with **Python and AWS** that analyzes historical ATP tennis match data and generates a Top 50 player ranking based on match wins.

The workflow uses **AWS Lambda** to process data stored in **Amazon S3**, saves the generated ranking back to S3, and sends an email notification through **Amazon SNS** after successful execution. **Amazon EventBridge** schedules the workflow to run automatically on a weekly basis.

## Project Overview

The project automates the complete processing workflow, from raw ATP match data to a generated player ranking and completion notification.

For each player, the analysis calculates:

- Total match wins
- Grand Slam wins
- Masters 1000 wins
- ATP 500 wins
- First recorded win
- Most recent win

Players are then ranked by total wins, and the **Top 50** are exported as a new CSV file.

## Data Source

The historical ATP match data used in this project comes from the **ATP Tennis 2000–2026 Daily Update** dataset available on Kaggle.

The dataset is licensed under **CC0: Public Domain**.

[View the dataset on Kaggle](https://www.kaggle.com/datasets/dissfya/atp-tennis-2000-2023daily-pull)

## Architecture

The workflow connects four AWS services:

- **Amazon EventBridge** schedules the pipeline to run automatically once a week.
- **AWS Lambda** executes the Python processing logic and calculates the Top 50 player ranking.
- **Amazon S3** stores the raw ATP dataset and the generated output files in separate `raw/` and `final/` locations.
- **Amazon SNS** sends an email notification after the analysis has been completed successfully.

```text
Amazon EventBridge
        │
        ▼
    AWS Lambda
        │
        ├── Reads ATP match data from S3 (raw/)
        │
        ├── Processes and aggregates data with Pandas
        │
        └── Generates the Top 50 ranking
        │
        ▼
    Amazon S3
      (final/)
        │
        ▼
    Amazon SNS
  Email notification
```

## Output

Each execution generates a dated CSV file containing the **Top 50 players ranked by total match wins**.

The output contains the following columns:

| Column | Description |
|---|---|
| `player_name` | Player name |
| `total_wins` | Total number of recorded match wins |
| `grand_slam_wins` | Wins in Grand Slam tournaments |
| `atp1000_wins` | Wins in Masters 1000 tournaments |
| `atp500_wins` | Wins in ATP 500 tournaments |
| `first_win` | Date of the player's first recorded win |
| `last_win` | Date of the player's most recent recorded win |

A generated example is included in:

```text
data/final/atp-top-50-25-07-2026.csv
```

The output filename is automatically generated using the execution date.

## AWS Configuration

The Lambda function uses environment variables to keep AWS resource configuration separate from the source code:

```text
BUCKET_NAME
SNS_TOPIC_ARN
INPUT_OBJECT_KEY
```

`INPUT_OBJECT_KEY` defaults to `raw/atp_tennis.csv`.

The Lambda execution role requires permissions to:

- Read the source dataset from Amazon S3
- Write generated output files to Amazon S3
- Publish notifications to Amazon SNS

Pandas is provided to the Lambda environment through an AWS Lambda layer.

## Running the Project

Install the required dependencies:

```bash
pip install -r requirements.txt
```

For AWS deployment:

1. Upload the source dataset to the `raw/` location in Amazon S3.
2. Configure the required Lambda environment variables.
3. Configure the Lambda execution role with the required S3 and SNS permissions.
4. Configure the Pandas Lambda layer.
5. Create an Amazon EventBridge schedule to trigger the Lambda function weekly.
6. Configure an Amazon SNS topic and email subscription for completion notifications.

The main processing logic is located in:

